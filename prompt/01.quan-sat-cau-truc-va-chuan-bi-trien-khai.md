# Quan sát cấu trúc và chuẩn bị triển khai

## Prompt
```
Bạn là chuyên gia kiến trúc microservices. Nhiệm vụ: QUAN SÁT và CHUẨN BỊ triển khai cấu trúc mới cho DocGO.

Bối cảnh:
- Dự án: DocGO (hệ thống quản lý tài liệu thông minh)
- Nhánh hiện tại: dev
- Kiến trúc hiện tại: 6 microservices (api-gateway-bff, authentication-identity-service, contract-management-service, ai-processing-service, file-storage-asset-service, web_nextjs)
- Mục tiêu: Chuyển đổi sang 4 microservices theo kiến trúc mới

Yêu cầu thực hiện:
1) **QUAN SÁT toàn bộ repo** hiện tại:
   - Liệt kê tất cả thư mục và file trong backend/
   - Liệt kê tất cả thư mục và file trong frontend/
   - Ghi nhận cấu trúc hiện tại và dependencies
   - Xác định các file cấu hình quan trọng (pom.xml, package.json, docker-compose.yml)

2) **CHUẨN BỊ mapping** cho việc chuyển đổi:
   - Tạo bảng mapping từ cấu trúc cũ sang cấu trúc mới
   - Xác định các file cần di chuyển
   - Xác định các file cần đổi tên
   - Xác định các file cần cập nhật cấu hình

3) **LẬP KẾ HOẠCH** triển khai:
   - Thứ tự thực hiện (không làm song song)
   - Các bước cần thiết cho từng service
   - Rủi ro và cách xử lý
   - Checklist kiểm tra sau mỗi bước

4) **BẢO VỆ** dữ liệu quan trọng:
   - Không xóa thư mục .cursor/
   - Không xóa thư mục .git/
   - Không xóa các file cấu hình quan trọng
   - Backup trước khi thực hiện

Đầu ra bắt buộc:
- **Báo cáo cấu trúc hiện tại** chi tiết
- **Bảng mapping** chuyển đổi
- **Kế hoạch triển khai** từng bước
- **Checklist** kiểm tra và rủi ro
- **KHÔNG thực hiện** bất kỳ thay đổi nào, chỉ quan sát và lập kế hoạch
```

## Mục đích
Quan sát toàn bộ cấu trúc hiện tại và lập kế hoạch triển khai cấu trúc mới

## Cách sử dụng
Copy nội dung prompt trên và paste vào chat AI để thực hiện quan sát và lập kế hoạch

**Lưu ý quan trọng:**
- Đang làm việc trên nhánh `dev`
- Tất cả thay đổi sẽ được thực hiện trên nhánh `dev`
- Không ảnh hưởng đến nhánh `vibe-coding` hoặc `main`
